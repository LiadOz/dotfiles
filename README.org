#+TITLE: Dotfiles source
#+DESCRIPTION: Portable source files deployed by workstation-config

* Purpose

This repository contains authored shell, editor, tmux, task, agent, and Linux
voice configuration. It is a source repository, not a live extension of the
home directory.

Deployment is owned by:

#+begin_example
~/projects/ai_stuff/workstation-config
#+end_example

The Ansible playbook copies only Git-tracked, named files into real directories
under =$HOME=. It does not replace =~/.local/bin=, =~/.config=, =~/.codex=, or
other machine-owned directories with links into this checkout. Existing
machine redirects, such as a scratch-backed =~/.codex= on a small home
filesystem, remain intact.

* Installation

From the workstation-config directory, first inspect the selected profile:

#+begin_src sh
./bootstrap --profile primary-linux --check --diff
#+end_src

Then apply and verify idempotence:

#+begin_src sh
./bootstrap --profile primary-linux
./bootstrap --profile primary-linux --check --diff
#+end_src

Other maintained profiles are =remote-worker= for TLV/farm machines and =mac=
for macOS. The remote profile never starts the speaker, Kokoro, Numen, or audio
services.

=./install.sh= is a compatibility entry point that delegates to the same
bootstrap. Set =WORKSTATION_CONFIG_ROOT= only if the orchestration checkout is
not at its default path.

* Repository boundaries

- Personal configuration and voice command launchers live here.
- The custom tmux plugin owns =agent-state=, =agent-pick=, and the selector UI;
  its source lives in =ai_stuff/tmux-agent-status= and Ansible installs its
  commands.
- The ccmux fork/patches live in =ai_stuff/ccmux=.
- Packages, host policy, service activation, and migration logic live in
  =ai_stuff/workstation-config=.
- Downloaded programs, Python environments, models, recordings, caches,
  secrets, and runtime state never live here.

* Machine-specific state

Taskwarrior reads =~/.config/task/taskrc.local=. Ansible creates it with mode
=0600=, but never puts its contents in Git. Other secrets belong in Ansible
Vault, an ignored host variables file, or the machine's secret manager.

The Neovim directory is a pinned Git submodule. Deployment uses its recorded
commit and copies tracked files; it does not merge the submodule's remote
branch during installation.
